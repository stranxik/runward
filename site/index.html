Why

Demos ship. Production kills.

Nearly everything that calls itself agentic dies between the demo and production. Not because the model is weak: nobody can evaluate a non-deterministic behavior, govern it, or say in advance when it fails. These are architecture problems, and agentic systems break four assumptions of classical engineering.

Non-deterministic core

Same input, different output, by design.

Input is instruction

Anything the model reads can try to command it.

Forgetting is engineering

Memory that only grows drowns the signal.

Unprecedented blast radius

An agent with tools acts on the world, not on text.

runward/rules/frontier-deterministic-boundary.md · impact: CRITICAL The model writes prose. The program owns the facts. Anything that can be retrieved, computed, validated or decided deterministically must live in code, never in the model's free generation. The model is rented and non-deterministic; the boundary around it is owned and tested. Why structured outputs are not enough: JSON schema guarantees the shape of the output, never its meaning. A model can emit a perfectly valid JSON number that is invented. Shape validation and truth validation are two different jobs. 1 of 51 craft rules shipped with every mission.

Is it for you

Three doors in. One door out.

Tech lead · working prototype

It runs on your machine. Production is next.

Enter through the brownfield workflow: characterize the existing system before touching anything, then re-enter the gates at the right tier.

Operator · regulated sector

You deliver for a client who will be audited.

Enter at Frame: day one is a conversation with your sponsor, not code. Governance is instrumented from day zero, never retrofitted.

Team · leaving Spec Kit / OpenSpec

The spec is written. Now it has to hold.

Your spec becomes the input of framing. The gates continue from there: floor, evidence, governance, handover.

Not for you if
  • An already-specified tooling request with no production stakes.
  • Recurring operations: Runward hands over, it does not operate.
  • A pure content or assistant use case, no tools, no blast radius.
  • You want a framework that decides for you. Runward makes you decide.
