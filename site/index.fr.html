runward/rules/frontier-deterministic-boundary.md · impact: CRITICAL The model writes prose. The program owns the facts. Anything that can be retrieved, computed, validated or decided deterministically must live in code, never in the model's free generation. The model is rented and non-deterministic; the boundary around it is owned and tested. Why structured outputs are not enough: JSON schema guarantees the shape of the output, never its meaning. A model can emit a perfectly valid JSON number that is invented. Shape validation and truth validation are two different jobs. 1 règle parmi les 51 règles de craft livrées avec chaque mission.

FAQ

Dès le jour un d'un nouveau projet d'agent : le cadrage est la première porte, avant toute spec. Depuis une spec existante (Spec Kit, OpenSpec, maison) : elle devient l'entrée du cadrage. Depuis un prototype existant : entrée par le code existant, caractériser avant d'y toucher.

Non. Runward est une méthode que votre agent de code exécute : des workflows en markdown, des livrables gardés par des portes, et une CLI qui les audite. Votre agent fait le travail ; un humain franchit les portes : human-in-the-loop par construction.

Spec Kit vous amène à un système spécifié et implémenté, et il le fait bien. Runward couvre la mission entière ; quand une spec existe, elle devient l'entrée du cadrage : plancher sur trafic réel, évolution sur preuve, gouvernance dès le jour zéro, passation avec preuve. Compatible en amont, par construction.
