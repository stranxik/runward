# Operator log — the intervention

The hours the runward maintainer spends between the two measures, **logged as they are spent** and
committed as they accumulate. The git history of this file is the evidence that `O` was not
reconstructed after the numbers were known — which matters, because `O` is half of the failure
criterion: the pilot counts against the method if `(T_before - T_after) < O`.

Round to the quarter hour. Include everything: reading the codebase, running `characterize`, writing
the mission, filling manifests, chasing evidence that would not resolve, re-running the gate. A log
that only counts the pleasant hours is a log that flatters the method.

## What is NOT counted here

- The engineer's time on either questionnaire run (that is `T_before` / `T_after`).
- Time spent on runward itself — a bug found during the pilot is fixed on runward's clock, not on
  this repository's. If a fix was needed to proceed, note it as a remark below rather than as hours;
  it is a finding about the tool, and the report says so.
